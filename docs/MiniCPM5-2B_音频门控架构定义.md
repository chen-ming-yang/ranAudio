## 1. 定位与设计目标

### 1.1 系统定位

一个**全双工语音交互系统**：快时钟 LM 槽位常驻，负责实时听、实时说、三路路由（简洁对话 / 本地 function call / 委派）；旁路 ASR 始终转写；需要强推理或复杂工具链时，把旁路 ASR 上下文交给异步慢时钟 LM。

链路与协议以 **§3.2** 为准。具体模型是可替换填充项（当前候选见 §3.2.4），未定时不得按 MiniCPM5-2B / Qwen3.5-27B 写死实现假设。

分工的**唯一原则**：

> **谁强谁承担推断责任。**
> FastLM：抽取式路由 + 简洁回答 + **本地**简单工具填槽；
> SlowLM：知识/多跳/复杂规划/需要强模型的工具链（仅 DELEGATE）。

### 1.2 设计目标（按优先级）

| 优先级 | 目标 | 为什么是它 |
|---|---|---|
| P0 | **主循环永不阻塞** | 全双工的地基。任何一处 `await` 工具返回，双工即失效 |
| P0 | 交互延迟 ≤ 600ms 出声 | 超过此值用户感知为「卡顿」 |
| P1 | 路由准确率（尤其**召回**） | 漏判 = 2B 硬答实时问题 = 幻觉，是最高代价的失败 |
| P1 | 打断/重叠鲁棒性 | 决定体验是否「像人」 |
| P2 | 端侧算力/内存预算 | 决定能否落地手机/车机 |
| P2 | 27B 调用成本 | 可被 filler 与分级路由优化 |

### 1.3 非目标（明确不做）

- 2B 端语音 token 生成（外接 TTS，2B 输出文本即可）
- 2B 多步规划 / 多轮 slot filling（v0.1 只做**一轮** function call）
- 主动交互（主动提醒、环境播报）—— MiniCPM-o 4.5 的 1Hz 主动决策[citation:4] 属于后续版本
- 视觉模态

## 2. 核心决策：旁路 ASR 始终开 + FastLM 三路由

### 2.1 决策内容

**旁路 ASR 始终运行**（与 FastLM 并行，不进 FastLM 解码主路径）。FastLM **首 token** 三选一：

```
对话：    <|NOFC|>今天天气不错，适合出门。
本地工具： <|FC|><|LOCAL|><function name="enable_bluetooth">
</function>
委派：    <|DELEGATE|>
```

- **NOFC**：简洁回答 / 听写正文 → TTS。不产生工具调用，不上抛。
- **FC+LOCAL**：本地出 `<function>` XML，L2 填槽执行。简单车机槽位优先走这里。
- **DELEGATE**：eos 即 fire-and-forget；**上派文本 = 旁路 ASR**（+ `anchor_time` / 可选多轮上下文），不是 FastLM 吐转写。

`<|BASE|>` 为 v0.2 历史兼容，**v0.3 三路由不再依赖 BASE 后转写上派**。本版 DELEGATE 后是否允许短垫话标 **OPEN**。

### 2.2 与其他方案的对比

| 方案 | 描述 | 优点 | 代价 |
|---|---|---|---|
| **A. 旁路 ASR + 三路由（本方案 v0.3）** | ASR 始终转写；FastLM 判对话/本地FC/委派 | 字幕与 SlowLM 上下文稳定；简单工具不占慢侧 | 多一路 ASR 算力；路由三类更难训 |
| B. 条件性 ASR（v0.2） | 只有命令路径才吐转写并上抛 | 省 ASR；端到端无文本中转 | 转写质量绑死 2B；不能本地 FC |
| C. 总是 ASR→再 LLM（纯级联） | 先转写再理解 | 模块独立 | 每轮强制文本中转；ASR 错必传播进决策 |
| D. 双流语音原生（Moshi 式） | 用户流/助手流并行自回归 | 保留副语言 | 需 speech tokenizer；端侧更重 |

### 2.3 决策依据与退路

选 A 的理由：产品要同时做到（1）实时字幕与委派上下文可靠，（2）简单工具端侧本地完成，（3）复杂能力异步委派——条件性 ASR 无法同时满足（1）（2）。

> **ASSUMPTION-A1**：2B 在简单闲聊上的端到端语音理解准确率可接受（NOFC 仍听音频，不依赖 ASR 文本）。
> 若 P0 实测 NOFC 听错率显著劣于「ASR 文本再答」，**可对 NOFC 也注入旁路 ASR 文本**（OPEN），不必退回纯级联。
> 判定方式见 §9.1。

### 2.4 已知代价与缓解

- **旁路 ASR 算力**：始终开；可用轻量流式 ASR / 与 S1.5 encoder 共用前端（OPEN）。
- **三路由训练难度**：LOCAL 与 DELEGATE 易混淆——造数时简单槽位标 LOCAL，知识/多跳/复杂策略标 DELEGATE；负例见 §10.4。
- **S1.5 仍保留**：旁路 ASR / FastLM 音频 encoder 的转写能力仍可沉淀在 encoder+projector；S2 不再要求主干吐 BASE 转写。

### 2.5 旁路 ASR 消费规则

> **硬规则：**
> 1. 旁路 ASR → **UI 字幕**（始终）。
> 2. 旁路 ASR → **DELEGATE 上派的 `asr_text` 唯一转写源**。
> 3. 旁路 ASR **不得**替代 FastLM 对 NOFC / LOCAL 的音频决策（除非开启 OPEN「NOFC 也读 ASR」）。
> 4. FastLM **不得**再靠吐转写上派；v0.2 的「主干转写才上派」作废。

## 3. 系统架构

### 3.1 分层

```
┌─────────────────────────────────────────────────────────────────────┐
│ L4  应用层      会话管理 · 工具沙箱 · 权限 · 审计                      │
├─────────────────────────────────────────────────────────────────────┤
│ L3  异步执行层   SlowLM Worker · 工具执行 · 结果回注                   │
│                 （慢时钟 0.5–5s，可取消，无状态于主循环）               │
├─────────────────────────────────────────────────────────────────────┤
│ L2  协调层      流解析 · 事件总线 · 状态机 · 播报仲裁                  │
├─────────────────────────────────────────────────────────────────────┤
│ L1  实时层      FastLM（三路由+本地FC+回复）· Encoder · 旁路ASR始终开 │
│                 （快时钟 80–160ms，永不阻塞）                          │
├─────────────────────────────────────────────────────────────────────┤
│ L0  信号层      AEC · 麦克风 · TTS 播放与回采                          │
└─────────────────────────────────────────────────────────────────────┘
```

槽位含义与当前候选见 §3.2.4。

### 3.2 数据流

```
         ┌────────────────────────────────────────────────────────────┐
         │  快时钟 80–160 ms/chunk（永不阻塞）                        │
         │                                                            │
         │  麦克风 ─► AEC ─┬─► Encoder ─► Adapter ─► FastLM          │
         │            │    └─► 旁路 ASR（始终开）──► 字幕 UI          │
         │            ▲                              │                │
         │            │  TTS 回采                     │ 单流自回归     │
         └────────────┴──────────────────────────────┼────────────────┘
                                                     │
         ┌───────────────────────────────────────────▼────────────────┐
         │  首 token = 三路由：NOFC / FC(+LOCAL) / DELEGATE            │
         └───────────────────────────┬────────────────────────────────┘
                                     │
      ┌──────────────────┬───────────┴───────────┐
      ▼                  ▼                       ▼
  <|NOFC|>+正文    <|FC|><|LOCAL|>+XML     <|DELEGATE|>
      │                  │                       │
      │                  │ 本地填槽执行     ① eos 即上派
      │                  │                  （asr_text=旁路ASR）
      │                  │                       │
      │                  │              ② emit（fire-and-forget）
      │                  │                       │
      │                  │            ┌──────────▼──────────┐
      │                  │            │ SlowLM（慢时钟）    │
      │                  │            │ 仅 DELEGATE 触发    │
      │                  │            │ → speak / no_op     │
      │                  │            └──────────┬──────────┘
      │                  │           ③ 结果回注  │
      └────────┬─────────┴───────────────────────┘
               ▼
     ④ TTS 出口（唯一汇合点：NOFC 正文 / 本地执行后话术 / 回注拼稿）
               │
          TTS 播放队列 ──回采──► AEC
```

**四个关键分叉点**：
- **① 上派时机**：`<|DELEGATE|>` 后 eos；`asr_text` 取自旁路 ASR，不是 FastLM 吐转写。
- **② fire-and-forget**：主循环不等待 SlowLM / 网络工具。
- **③ 结果回注**：异步事件；播报由仲裁决定（§6.2）；不得直达扬声器。
- **④ TTS 出口**：NOFC、本地执行后的话术出口、回注拼稿的唯一汇合点。

本节图是整体链路的**唯一脊柱**。后文协议（§4）、时钟（§5）、状态机（§6）都挂在这张图上，不另起并行数据流。

### 3.2.1 四条铁律

从图上四个分叉点落成约束。实现不得走样：

1. **DELEGATE 后 eos 即 emit**；`asr_text` = 旁路 ASR。本版 DELEGATE 后垫话标 **OPEN**。
2. **emit 必须 fire-and-forget**：快时钟不得 `await` Worker；本地 FC 在端侧执行，亦不阻塞慢侧。
3. **回注是事件，不是出声**：出声与否由播报仲裁决定（`no_op` / `speak=null` / 用户正在说则挂起，见 §6.2）。回注不得直达扬声器。
4. **只有一个 TTS 汇合点**：NOFC 正文、本地执行后话术、回注拼接稿只能进 ④；禁止旁路 ASR 或 SlowLM 直接播。

### 3.2.2 模块与职责

按图上的框定义输入 / 输出 / 不得做什么。不规定实现语言或框架。

| 模块 | 层 | 输入 | 输出 | 不得做什么 |
|---|---|---|---|---|
| 麦克风 | L0 | 声学 | PCM chunk（80–160 ms） | — |
| AEC | L0 | 近端=麦；远端=TTS 回采 | 残差音频 | 不得把旁路 ASR 当残差源 |
| 旁路 ASR | L1 | AEC 残差 | 转写文本（始终） | 不得替代 FastLM 的 NOFC/LOCAL 决策；不得直达 TTS |
| Encoder 槽位 | L1 | AEC 残差 chunk | 音频表示（流式） | 不得整段非流式堵住快时钟 |
| Adapter | L1 | 音频表示 | FastLM 隐空间 | — |
| FastLM 槽位 | L1 | Adapter 输出 | 单流自回归 token（三路由） | 快时钟内不得等待网络 / SlowLM |
| 首 token 路由 + 流解析 | L2 | token 流 | NOFC / FC+LOCAL / DELEGATE | 半标签处理必须满足 §4.2 |
| 本地 FC 执行器 | L2 | function XML | 端侧动作 + 可选话术 | 不得把简单槽位再丢 SlowLM |
| 事件总线 | L2 | dispatch / result / cancel | 单向投递 | 不得让快时钟 `await` |
| 播报仲裁 | L2 | 回注 + 交互状态（§6） | 是否允许 `tts.enqueue` | 回注不得直达扬声器 |
| SlowLM Worker | L3 | `route.dispatch`（仅 DELEGATE） | `route.result` | 对主循环无状态；简单车机槽位不应进此路径 |
| TTS 出口（④） | L2→L0 | NOFC / 本地话术 / 回注拼稿 | 分句 + 文本规整 | 禁止旁路绕过本口 |
| TTS 播放队列 | L0 | 规整后文本 | 播放音频 + 回采参考 | 回采只回 AEC，不回 FastLM 文本侧 |

SlowLM 一轮 FC 的顺序固定为：`LLM(tools) → 执行 → 回填 → LLM → speak`（仅 DELEGATE）。

### 3.2.3 路径不变量

- **NOFC**：简洁回答 / 听写正文 → ④。不上派；不依赖旁路 ASR 文本（除非 OPEN）。
- **FC+LOCAL**：`<function>` XML 由 L2 本地解析执行。不上抛 SlowLM。
- **DELEGATE**：eos 上派；**`asr_text` 唯一源 = 旁路 ASR**。另带 `request_id` / `anchor_time` / 可选 `prev_utterance`（§4.3）。
- **BASE**：v0.2 历史；v0.3 三路由不再靠 BASE 后转写上派。
- 回注负载沿用 §4.4。`speak=null` 表示本轮不播报。

### 3.2.4 模型槽位

具体型号后续填充。每个槽位只规定**必须满足的能力**；当前候选仅作脚注，不是实现前提。

| 槽位 | 必须满足 | 当前候选 |
|---|---|---|
| **Encoder** | 流式、chunk-causal；输入 AEC 残差，输出音频表示 | **SenseVoice-Small**（[`ranAudio/sensevoice_apm.py`](../ranAudio/sensevoice_apm.py)；Whisper APM 仅保留给 v1.0 对照） |
| **旁路 ASR** | 始终可出转写；延迟可接受于字幕与 DELEGATE 上下文 | **OPEN**（可与 S1.5 encoder 前端共用或独立轻量 ASR） |
| **FastLM** | 端侧可常驻；**首 token** 给出 NOFC / FC / DELEGATE；LOCAL 后能吐合法 function XML | MiniCPM5-2B |
| **SlowLM** | 仅 DELEGATE；一轮 FC + 回填后再 `speak`；按 `request_id` **取消**；能 `no_op`（`speak=null`） | Qwen3.5-27B |
| **TTS** | 文本进、音频出，并提供回采参考给 AEC | **OPEN**（未选型） |

槽位更换后：链路与协议不变；§10 训练规格须重做，不得把针对当前 FastLM 候选的阶段 / loss 当成与型号无关的硬约束。

### 3.2.5 事件与失败路径

总线只定义事件名与触发点。字段表见 §4.3 / §4.4，此处不重复。

| 事件 | 触发 | 去向 |
|---|---|---|
| `route.dispatch` | `<|DELEGATE|>` 后 eos（铁律 1）；附旁路 ASR `asr_text` | SlowLM Worker |
| `local.execute` | `<|FC|><|LOCAL|>` + function XML 解析完成 | 端侧工具执行器 |
| `route.result` | Worker 完成 / 失败 / 取消 | 播报仲裁，不得直达扬声器 |
| `route.cancel` | 打断确认 | Worker；FastLM 侧回滚见 §6.3 |
| `tts.enqueue` | 仲裁放行后的唯一入口 | TTS 播放队列 |

失败影响与 §5 一致：

- **慢时钟**超时 / `error`：降级为本地应答，或闭嘴（`speak=null`）。交互不中断。
- **快时钟**失败：交互中断。这是唯一允许打断主循环的失败。
- 取消语义与回滚深度见 §6.3，本节不展开状态机。

### 3.2.6 本版回注落地（`<backend>`）

相对铁律 3「回注不进 FastLM」：本版把 `route.result` 的 `speak` 写成 user 侧标签，与当前音频 pads **同一次** 前向进 FastLM，由 2B 拼成一段给 TTS 的话。回注仍不得旁路直达扬声器。

```text
<backend>北京明天多云转晴，18到24度。</backend><|audio_start|>…pads…<|audio_end|>
→ <|NOFC|>查到了，北京明天多云转晴，18到24度。
```

- `<backend>` / `</backend>` 是 **输入标记**（special token），2B 不回吐。
- 标签内事实原样进入输出（数字、专名不得改写）。
- 与音频 Cond 输出拼成 **一段** `<|NOFC|>` 正文，可加衔接，供 TTS。
- 无回注时不要空标签。S2 本版不训此条，词表先加齐。细节见 [S2 §2.1](./S2_FC_NOFC_训练计划.md)。

## 4. 输出协议

> **Draft v0.3 字面。** 仓库 `protocol.py` / 已训权重仍为旧 S2（FC+BASE+NOFC）；实现另开，不得按本文直接改训练脚本。

### 4.1 Token 流格式

所有信息在**单一自回归序列**中，无并行流。

| 段 | 字面 | 出现条件 | 消费方式 |
|---|---|---|---|
| 对话 | NOFC + 正文 | 闲聊回答或听写正文 | 流式送 TTS |
| 本地工具 | FC + LOCAL + `<function>` XML | 简单车机槽位，端侧可执行 | L2 解析后本地执行 |
| 委派 | DELEGATE（本版默认不跟转写正文） | 知识/多跳/复杂规划 | eos 即上派；`asr_text`=旁路 ASR |
| BASE（历史） | FC + BASE + 转写 | v0.2 / 旧代码 | **v0.3 三路由不再使用** |

词表：保留现有 token，**新增 `<|DELEGATE|>`**；启用原预留 `<|LOCAL|>`。`<backend>` 只在 user 输入。

```text
<|NOFC|>今天天气不错，适合出门。
<|FC|><|LOCAL|><function name="enable_bluetooth">
</function>
<|DELEGATE|>
```

LOCAL 的 XML 形态对齐 [minicpm5_fc_format.md](./minicpm5_fc_format.md)（`<function name="...">` / `<parameter>`）；SFT **默认不传 `tools=`**，靠 system / 示例教 XML，推理侧本地执行器解析。

### 4.2 流式解析约束（实现必须满足）

标签会被切在不同 token 中。解析器必须满足：

1. **半个标签保留**：pending 是标签前缀时**原样保留**等补齐，不得清空（清空会导致后续 token 无从拼接，标签残骸漏进正文）。
2. **前缀显式等待**：三态判定——完整匹配→剥离 / 是前缀→等待 / 都不是→降级。缺失「等待」态会导致半个标签被判为正文。
3. **降级不等长度**：一旦确定不是任何标签前缀，立即降级为 NOFC 正文。不得等攒够固定长度（中文短句永远凑不齐，会导致整句不播报）。
4. **异常不吞**：`<|DELEGATE|>` 未完整闭合时不得误 emit；`<|FC|><|LOCAL|>` 后 XML 未闭合时不得半截执行——有多少缓冲多少，等合法边界再消费。

> 实现备注：这四条是此类设计的通用陷阱，与具体语言无关。验收需覆盖 1/2/3/5/7/N 多种切分粒度 + 无标签降级 + 标签未闭合。

### 4.3 上派负载

仅 **DELEGATE** 路径发出。转写**不来自 FastLM**：

```jsonc
{
  "request_id":  "req_xxx",        // 用于取消
  "asr_text":    "帮我查一下北京天气",  // 旁路 ASR（唯一转写源）
  "anchor_time": "2026-09-10T14:23:00+08:00",  // 用户说话时刻，解析「明天」必需
  "prev_utterance": "…"            // 可选：上一句用户原话 / 多轮上下文
}
```

**`anchor_time` 必带**。缺了它，SlowLM 无法解析任何相对时间表达。用**说话时刻**，不是接收时刻。

### 4.4 回注负载

```jsonc
{
  "request_id": "req_xxx",
  "status": "ok | need_clarify | no_op | cancelled | error",
  "speak": "北京明天多云转晴，18到24度。",   // null = 本轮不播报
  "tool_trace": [...]
}
```

`no_op` 是**必要的**：worker 默默更新了信息但无需打扰用户时，必须能闭嘴。全双工里「没事找事式插播」是高频体验杀手。

## 5. 时钟模型

| | 快时钟 | 慢时钟 |
|---|---|---|
| 周期 | 80–160 ms/chunk | 0.5–5 s |
| 承载 | 听、说、三路由、本地 FC | 仅 DELEGATE：复杂 FC / 规划 |
| 阻塞 | **永不** | 可被取消 |
| 失败影响 | 交互中断 | 降级为本地应答 |

**铁律**：快时钟内不出现任何网络/工具等待。所有跨时钟交互通过事件总线，单向 fire-and-forget + 异步回注。

## 6. 状态机

### 6.1 交互状态

五状态，覆盖全双工主要情形：

| 状态 | 含义 | 进入 | 退出 |
|---|---|---|---|
| `LISTEN` | 听，未决策 | 静默/开启 | 端点检测触发 |
| `SPEAK` | 播报中 | 决策为 NOFC / 收到回注 | 播完或被打断 |
| `ROUTE_WAIT` | 已上派，等结果 | DELEGATE 后 eos | 结果回注 / 取消 |
| `DUAL` | 重叠（双方同时说） | 播报中检测到用户语音 | 判定为 backchannel 或 barge-in |
| `BARGE_IN` | 被打断 | 确认打断 | 取消在途，转 LISTEN |

> `WAIT`（静默但未结束）与 `DUAL` 是区别于简单 speak/listen 二分的关键：
> 停顿不等于说完，重叠不等于打断。

### 6.2 播报仲裁（关键规则）

> **用户正在说话时，不主动插入播报。**
> 回注结果到达时若处于 `LISTEN`/`DUAL`（用户在说），挂起到 `on_silence` 再播。

违反此规则的典型失败：用户正说着，AI 硬插一句上一轮查的天气。

### 6.3 取消语义

- `barge_in` → 对 `request_id` 发 `cancel`
- 2B 侧状态回滚到上派前快照
- **worker 侧回滚深度由 worker 决定**（v0.1 单轮 FC，通常整体丢弃）

**OPEN-1**：多轮任务下 worker 回滚深度（整体丢弃 / 保留已完成副作用）未定义。副作用不可逆时（如已下单）的补偿语义需单独设计。

### 6.4 回声与打断

- **信号层**：WebRTC AEC，TTS 播放音频作为参考
- **模型层**：训练时混入 TTS 播放音频 + 用户插入音频的随机偏移，标注忽略/打断
- 打断检测建议采用 **chunk 级状态预测**（模型最后一层挂分类头），而非外挂 VAD

**OPEN-2**：CF（通道融合）与 XA（cross-attention 路由）的选择。研究显示 CF 语义更强但打断时易产生错乱续生成，XA 打断鲁棒性更好[citation:26]。**当前倾向混合**——主干 XA 保播放连贯，门控分支 CF 保语义。

## 7. 端到端时序

### 7.1 正常回复（NOFC）

```
t=0     端点检测
t=50    <|NOFC|> 吐出            → 路由确定
t=80    首个分句送 TTS
t=350   首包出声                 ← 用户感知延迟
t=1.2s  全部播完
```

### 7.2 本地工具（FC+LOCAL）

```
t=0     端点检测
t=50    <|FC|><|LOCAL|>
t=120   function XML 闭合         → 本地执行
t=200+  可选话术进 ④ → TTS
```

### 7.3 委派上派（DELEGATE）

```
t=0     端点检测（旁路 ASR 已在转写）
t=50    <|DELEGATE|>
t=80    eos                       → 立即上派 ①（asr_text=旁路 ASR）
t=80+   SlowLM 执行（1–3s）
t=2.5s  结果回注 → FastLM 拼 NOFC → 播报
```

DELEGATE 后是否允许短垫话标 **OPEN**；若允许，不得用垫话冒充 `asr_text`。

### 7.4 打断

```
t=0     上派 req_a
t=200   用户插话（VAD/chunk 预测）
t=200   cancel(req_a)，2B 状态回滚
t=250   处理新输入
```

### 7.5 延后播报

```
t=0     上派 req_a
t=1.5s  req_a 结果回来，但用户在说话 → 挂起
t=3.0s  on_silence → 播报
```

## 8. 延迟预算

| 环节 | 预算 | 备注 |
|---|---|---|
| 音频 chunk | 80–160 ms | 下采样至 ~12.5Hz 与文本 token 率接近 |
| 端点检测 | 100–300 ms | 语义端点优于纯静音检测 |
| 路由决策 | 1 个 token | 本设计的核心优势 |
| 首包出声（NOFC） | 300–600 ms | 含 TTS 首包 |
| 本地 FC | XML 闭合即执行 | 不经慢侧 |
| DELEGATE 上派 | DELEGATE eos 即 emit | `asr_text` 旁路 ASR；垫话 OPEN |
| 结果播报（委派） | +1–3 s | 经 FastLM 拼 NOFC |

**ASSUMPTION-A2**：2B 在目标硬件（INT4，端侧 NPU/CPU）上解码速率 ≥ 20 tok/s。低于此值 filler 策略失效，需重新评估。

## 9. 验证与评测

### 9.1 推翻 ASSUMPTION-A1 的判定实验（P0）

构造对照集（各 200 条，覆盖：问候、闲聊、情感回应、简单知识、指令），对比：

- **准确率**：语义是否正确
- **听错率**：是否因误识别而答非所问

**判定**：若 2B 端到端 NOFC 在「听错率」上显著劣于「旁路 ASR 文本再答」（> 1.5×），优先试 OPEN「NOFC 也读 ASR」，不必立刻退回纯级联。

### 9.2 路由指标（P1）

| 指标 | 定义 | 目标 |
|---|---|---|
| **DELEGATE 召回** | 该委派且委派 / 该委派 | **≥ 0.95**（优先保证） |
| DELEGATE 精确 | 该委派 / 实际委派 | ≥ 0.80 |
| LOCAL 精确 / 召回 | 简单槽位是否走本地 FC | ≥ 0.90 / ≥ 0.90 |
| LOCAL↔DELEGATE 混淆率 | 简单槽位误委派 + 复杂误本地 | 尽量低；造数边界见 §10.4 |
| 旁路 ASR CER（DELEGATE 子集） | 上派 `asr_text` 字符错误率 | ≤ 0.08 |
| **实体 / 数字保真率**（旁路 ASR） | 专名、数字、时间未被「脑补」改写 | ≥ 0.98 |

**委派召回优先于精确**：漏委派代价（幻觉/答不出）高于误委派（多一次延迟）。简单槽位则优先 LOCAL，避免占慢侧。

### 9.3 交互指标（P1）

打断成功率、误打断率（backchannel 误判为打断）、重叠播报率、首包延迟 P50/P95。

## 10. 训练规格

> 本节针对**当前快时钟 LM 候选**（MiniCPM5-2B）及配套 encoder。槽位更换后须重做阶段划分与 loss，不得把本节当作与型号无关的硬约束。
>
> **v0.3 仅文档约定**；现有 S2 `mix_boundary` / `protocol.py` 仍训旧 FC+BASE+NOFC。三路由实现另开。

### 10.1 数据格式（三路由）

```
对话：    <audio> → <|NOFC|>正文
本地工具： <audio> → <|FC|><|LOCAL|><function name="...">...</function>
委派：    <audio> → <|DELEGATE|>
```

- SFT **默认不传 `tools=`**；LOCAL 用 system / 示例教 MiniCPM5 风格 XML（见 [minicpm5_fc_format.md](./minicpm5_fc_format.md)）。
- DELEGATE **本版默认不跟转写正文**；上派文本由旁路 ASR 在推理时提供。
- 简单车机槽位 → LOCAL；知识/多跳/复杂规划 → DELEGATE；能本地答对的 → NOFC。

> **数据量级**：S1.5 仍用大规模 ASR 训 encoder（旁路 ASR / FastLM 前端对齐）。S2 **不再**要求主干吐 BASE 转写；旁路 ASR 质量与 encoder 对齐仍靠 S1.5。

### 10.2 Loss 策略

| 段 | 权重 | 理由 |
|---|---|---|
| 路由 token（NOFC / FC / LOCAL / DELEGATE） | **≥ 1.0**（单独提权） | P1 核心指标，不得被稀释 |
| NOFC 后正文 | 1.0 | 2B 的对话核心产出 |
| LOCAL 后 function XML | 1.0 | 本地执行合法性依赖完整 XML |
| DELEGATE（通常仅路由 token） | ≥ 1.0 | 与 NOFC/LOCAL 三分边界 |
| BASE 后转写（仅旧协议兼容集） | 0 或极低 | v0.3 主训不依赖 |

- **纯文本回放用「交错」而非「混批」**：dataset-level 简单混合无法把文本侧能力迁移到语音侧——应在对齐的语音-文本对内部构造 **segment 级交错序列**。
- **先分后混**：三路由任务先各自收敛再混合，或交替 batch。

### 10.3 阶段划分

| 阶段 | 目标 | 冻结 |
|---|---|---|
| S0 模态对齐 | encoder + adapter | 冻结 2B |
| S1 流式化 | encoder 改 chunk-causal | 冻结 2B |
| **S1.5 ASR 对齐（关键）** | 大规模 ASR，沉淀转写到 encoder / 旁路 ASR 前端 | **2B 完全冻结（不开 LoRA）** |
| S2 三路由 SFT | NOFC / FC+LOCAL / DELEGATE | **2B 用 LoRA，不全参** |
| S3 路由校准 | 扫 LOCAL↔DELEGATE↔NOFC operating point | 免重训调阈值 |
| S4 双工专项 | 合成重叠语音，训打断与回声忽略 | LoRA |

**硬约束**：2B 不得全参微调。语音化后文本智能退化是这类系统的典型失败模式。

> **S1.5 仍关键**：旁路 ASR 与 FastLM 音频前端的转写/对齐能力在此沉淀。v0.3 只是把「主干吐转写上派」从 S2 拿掉，不是取消 S1.5。

### 10.4 负例构造（关键）

> **必须让 2B 自己先答一遍，能答对的标 NOFC。**
> **简单槽位标 LOCAL，不得标 DELEGATE；复杂/知识标 DELEGATE，不得标 LOCAL。**

否则模型会发现「委派总是安全的」或「本地总是省事」，三路由退化。Hard negative 重点：闲聊、角色扮演、简单算术、开关类本地工具 vs 天气/多跳查询。

**OPEN-3**：负例与正例比例、LOCAL/DELEGATE 边界自动化未定义。

### 10.5 多任务冲突：路由 × 生成 ×（可选）转写

**v0.3 主冲突变为**：NOFC 自由生成 vs LOCAL 结构化 XML vs DELEGATE 短路由——三者共享 decoder。旧版「BASE 转写 × NOFC 生成」冲突因主干不再吐转写而**大幅缓解**；旁路 ASR 独立，不再与生成抢主干容量。

若仍混入旧 BASE 兼容样本，则转写×生成冲突分析（Phi-4 式阶段隔离）仍然适用——但那是兼容路径，不是 v0.3 主路径。

#### 决策

1. **S1.5 继续**：encoder / 旁路 ASR 前端对齐（2B 冻结）。
2. **S2 三路由**：不训主干 BASE 转写；LOCAL XML 与 NOFC 正文权重并列。
3. **路由 token 提权**：NOFC / FC / LOCAL / DELEGATE ≥ 1.0。
4. **文本回放改交错 + 先分后混**（§10.2）。
5. **可选**：encoder 侧辅助 ASR head（OPEN-7）服务旁路 ASR，不占主干生成容量。

#### 必须监控的失效信号

| 信号 | 表现 | 危险点 |
|---|---|---|
| **LOCAL/DELEGATE 混淆** | 开关类上抛或复杂查询本地瞎填 | 慢侧浪费 / 端侧幻觉参数 |
| **回复复读化** | NOFC 后复述用户而不回答 | 触发 §2.3 ASSUMPTION-A1 |
| **委派率漂移** | DELEGATE 率随训练单调上升 | §10.4「全部委派」退化 |
| **旁路 ASR 脑补** | 上派 `asr_text` 改写实体/数字 | 污染 SlowLM 上下文 |

#### 判定实验（S2 前必做）

扫三路由配比与 LOCAL XML 权重，记录：

1. DELEGATE 率 / LOCAL 率 / NOFC 率
2. LOCAL↔DELEGATE 混淆率
3. NOFC 闲聊复读率
4. 旁路 ASR CER + 实体/数字保真率（DELEGATE 子集）

另用 **T2T vs S2T** 差值诊断生成先验保留度。

**OPEN-7**：旁路 ASR 与 FastLM encoder 是否共用前端；辅助 ASR head 形态未定。

## 11. 开放问题

| ID | 问题 | 影响 | 收敛时点 |
|---|---|---|---|
| **OPEN-1** | 多轮任务下 worker 回滚深度与副作用补偿 | 高（涉及资金/订单安全） | 实现前 |
| **OPEN-2** | CF / XA 用户流路由方式选择 | 高（决定打断鲁棒性） | P1 实测 |
| **OPEN-3** | 负例比例与 LOCAL/DELEGATE 边界自动化 | 中（决定三路由是否退化） | S2 三路由实现前 |
| **OPEN-4** | 任务级迟滞是否纳入 | 中（决定多轮省略句能力） | 后续版本 |
| **OPEN-5** | SlowLM 分级（新任务 pro / 续接 lite）必要性 | 中（成本） | 成本实测后 |
| **OPEN-6** | 端点检测：语义端点 vs 静音端点 | 中（延迟） | P0 |
| **OPEN-7** | 旁路 ASR 与 FastLM encoder 是否共用；辅助 ASR head | 中 | P0 实测 |
| **OPEN-8** | DELEGATE 后是否允许短垫话 | 中（感知延迟） | 本轮不定 |

### 关于 OPEN-4 的说明（当前明确不做）

当前路由是**无状态三分类**。这意味着「那明天呢」「要靠窗的」这类**省略句仍难正确路由**——2B 单独看这句可能提取不出意图。

已知解法是**任务级迟滞**：任务进行中默认 DELEGATE，只判是否离题/终止。需要 `task_id` 粘性与任务状态。

**当前取舍**：先接受这个缺陷，用三路由 + 一轮 SlowLM FC 换架构可验证性；多轮省略句后续再解。

## 12. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 2B 端到端 NOFC 听错率过高 | 闲聊答非所问 | 试 OPEN「NOFC 也读 ASR」（§2.3） |
| 三路由退化为「全部 DELEGATE」或 LOCAL/DELEGATE 混淆 | 成本失控 / 端侧幻觉 | 负例构造（§10.4）+ 审计委派率 |
| 2B 语音化后智能退化 | 闲聊质量崩塌 | LoRA + 交错式文本回放（§10.2、§10.3 硬约束） |
| 旁路 ASR 错误污染 SlowLM | 委派答非所问 | S1.5 + 实体/数字保真率（§9.2） |
| 工具返回被模型覆盖 | 说出假数据 | 工具报错如实回填；回注经 FastLM 拼 NOFC |
| 长文本/长任务超时 | 交互卡死 | 超时即降级本地应答 / `speak=null` |
