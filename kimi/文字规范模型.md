# 文字规范模型：讨论结论

**日期**：2026-10-24  
**范围**：Qwen3-ASR 转写之后的文字规范后处理。语音修改指令不在本文实施范围内。  
**状态**：当前使用版本 **v3**。迭代记录和测试结果见 [文字规范模型版本.md](文字规范模型版本.md)。

## 1. 要解决的句子

Qwen3-ASR-1.7B 把口述听成：

> 我叫陈明阳，明是名字的明，阳是提手旁的阳。

目标是：

> 我叫陈名扬，名是名字的名，扬是提手旁的扬。

同音字靠声学分不开。正确字形写在后半句的组词和偏旁里。后处理要按这些说明改姓名，也要改说明本身。

## 2. 两种模型

两条链路分开，不共用一个适配器。

| | 文字规范模型（现在做） | 语音指令模型（以后另做） |
|---|---|---|
| 输入 | ASR 转写全文 | 已有文稿 + 语音里的修改指令 |
| 用户是否另下命令 | 否 | 是，例如「把第三句改成…」 |
| 行为 | 按固定规范改字 | 按这句话的要求改文稿 |
| 现有代码 | 尚无这条训练链路 | [`scripts/demo_web.py`](scripts/demo_web.py) 的改写路径 |

```text
ASR 全文 ──► 文字规范 LoRA ──► 规范后文本

已有文稿 ──┐
           ├──► 语音指令模型 ──► 按要求改后的文稿
语音指令 ──┘
```

没有额外命令时，多种规范都进文字规范模型。模型从全文自己判断该用哪条规范。

## 3. 试跑结论（2026-10-24）

本机关闭 thinking、贪心解码。Prompt 里不放字表时，模型不会稳定按拆字改字。

| 模型 | 条件 | 结果 |
|---|---|---|
| Qwen3.5-2B | 只有「李清 / 三点水」示例 | 原句原样返回 |
| Qwen3.5-2B | prompt 中写入「陈明阳 → 陈名扬」 | 姓名变成「陈名阳」，说明变成「扬」，前后不一致 |
| Qwen3.5-9B | 只有「李清」示例 | 原句只改成「陈明扬」，「名」没改出来 |
| Qwen3.5-9B | prompt 中写入原句的标准答案 | 换姓的「赵明阳…提手旁的阳」能改成「赵名扬」；「杨是提手旁的杨」原样返回；「铁手旁的羊」只改了姓名 |

少样本只能记住写过的句式。汉字和偏旁的组合补不进 prompt。

## 4. 训练决定

- **基座**：[`/cmy/cmy/Qwen/Qwen3.5-2B`](/cmy/cmy/Qwen/Qwen3.5-2B)。
- **方式**：LoRA，打在 `q/k/v/o/gate/up/down`。脚本形式沿用 [`scripts/sft_spoken2written.py`](scripts/sft_spoken2written.py)：关闭 thinking，loss 只打在纠正句上。
- **不做全量微调**。规范是照抄中文之上的薄一层。全量会反复改整个 2B，普通句更容易被带偏，每加一种规范也更贵。
- **不训 9B**。9B 零样本更强，是因为它还能照 prompt 里的例句套。微调之后目标字来自数据。9B 更慢，还要和 Qwen3-ASR-1.7B 抢显存。
- **不用** Kimi-Audio-7B。这条链路只吃文本。
- **不用**在线规则引擎，也不用 `has_name_clarify` 决定是否调用模型。现有 `resolve_name_clarify` 对「阳 + 提手旁 → 扬」有效，对「明是名字的明」会留成「明」，整句变成「陈明扬」。

LoRA 与全量微调的差别：全量更新 2B 的全部参数，得到一份新的完整模型。LoRA 冻住基座，只训练旁边的低秩矩阵，适配器通常几十 MB。推理时把适配器贴回基座。

推理 prompt 只保留短指令，不含字表，不含「陈名扬」示例：

- 若原文用组词或偏旁说明字形，把姓名和说明改成同一个正确字。
- 没有这类说明则原样输出。
- 只输出全文。

## 5. 合成数据

字表只用来造数据，不进 prompt。输出 `eval_name_clarify/sft/{train,val}.jsonl`，每条是原文和纠正。

| 类别 | 大约比例 | 内容 |
|---|---|---|
| 组词，两侧都错 | 40% | 从常用词抽出目标字，用同音字当 ASR 表面，姓名和「X是…的X」两侧都写成该同音字 |
| 偏旁口误 | 30% | 偏旁描述加声旁或同音表面，映射到正字。铁手旁视为提手旁。表只作数据源 |
| 已经正确 | 15% | 如「明是明日的明」，标签等于原文 |
| 普通句 | 15% | 没有字形说明，标签等于原文 |

姓、字数、句号随机。训练集不出现姓名「陈名扬」。规模大约 8k 训练 / 400 验证。验证集必须包含：

- `我叫陈明阳，明是名字的明，阳是提手旁的阳。` → `我叫陈名扬，名是名字的名，扬是提手旁的扬。`
- `我叫陈明阳，名是名字的名，杨是提手旁的杨。` → 姓名与说明都改为名、扬
- `我是陈名杨，名是名字的名，杨是铁手旁的羊` → `我是陈名扬，名是名字的名，扬是提手旁的扬`
- `我是李小明，明是明日的明` 保持不变
- `今天天气不错，适合出门散步。` 保持不变
- 若干训练中没出现的偏旁组合

输出目录：`eval_name_clarify/sft_out/qwen35_2b_lora`。

验证集里上述纠正句全部正确，才把模型接到 L1。不过线就加数据重训，不改成全量，也不换成 9B，不在 prompt 里堆例子。

## 6. 以后增加规范

多种规范共用这一个 LoRA。新规范补一批合成句，与旧数据混合后再训一版，旧数据保留，避免忘掉拆字。不为每种规范单独挂适配器。语音指令的需求不进这份数据。

换一版权重时，推理入口仍是「ASR 全文进、全文出」。

## 7. 接入 L1（评测通过之后）

流式 partial 不跑这个模型。

1. [`scripts/l1_server.py`](scripts/l1_server.py) 先发 ASR `final`。
2. 每条 final 无条件、异步送入 2B + LoRA。贪心解码，`max_new_tokens` 约 128。
3. 另发 `{type:"postprocess", text, via:"llm_postprocess"}`。
4. 页面用 postprocess 替换主文本。失败时保留 final。

启动参数 `--llm-postprocess` 默认开启。不改 cdsd，也不改音素个性化路径。
